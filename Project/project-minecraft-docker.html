Minecraft Docker

A containerised Minecraft server deployed with Docker, with persistent world data and a repeatable setup that runs the same on any host.

Overview

Running a game server by hand means installing the right Java version, remembering the launch flags and hoping nothing breaks when you move machines. This project packages the whole server in a Docker container so it can be started with one command and behaves identically everywhere, while the world itself is kept safe in a persistent volume.

What I built

  • A Dockerised Minecraft server with a repeatable configuration
  • A volume so world data survives container restarts and upgrades
  • Port mapping so players can connect to the server
  • Settings such as memory limits kept in configuration, not in my head

How it works

  1. Pull or build the server image.
  2. Start the container with the game port published and a data volume mounted.
  3. Players connect to the host's address and port.
  4. Stop, update or move the container without losing the world.

Example setup

The general shape of the command, shown as an illustration. Replace with the exact configuration from your repository.

docker run -d --name minecraft \
  -p 25565:25565 \
  -v minecraft-data:/data \
  -e EULA=TRUE \

What I learned

Containers separate the application from the machine, which is what makes deployments repeatable. Persistent volumes taught me to treat data and the running container as two different things.
